# Нулевая точка машинного входа

Этот документ разворачивает машинную навигационную матрицу. Машиночитаемая загрузочная матрица находится в `AGENT_BOOTSTRAP_MANIFEST.json`.

## Одна функция

Шесть архитектурных репозиториев помогают до уверенного ответа разложить происходящее по ответственным частям:

```text
кто здесь кто
→ из чего состоит текущая среда
→ что она фактически может сейчас
→ было ли действие выполнено
→ что именно продолжилось после изменения
→ как связаны разные следы
→ по каким источникам это проверено
```

Они не образуют единую нормативную систему и не передают выводы друг другу. Каждый компонент отвечает только за собственную область.

## Компоненты

### ARB — границы

Agent Runtime Boundaries разделяет человека, агента, модель, runtime/host, платформу, состояние, память, инструменты и свидетельства.

### MPAA — архитектура и текущая форма

Minimal Portable Agent Architecture описывает состав среды исполнения, identity profile, разрешения, способности, состояние задачи и Runtime Report.

### BEC — исполнение

Behavioral Execution Contract отделяет наличие инструмента и рассказ о действии от разрешения, вызова, результата, evidence и trust anchor.

### PCA — продолжение процесса

Process Continuity Architecture проверяет ограниченные утверждения о продолжении после смены модели, носителя, среды, корпуса или режима использования.

```text
продолжение процесса
≠ тождество личности
≠ доказательство сознания
≠ непрерывное существование без разрыва
```

### CDTS — связь следов

Cross-Domain Trace Set связывает адресуемые записи разных компонентов, не присваивая их выводы.

```text
переноси след,
а не чужое заключение
```

### Repository Canon Review Protocol — источники

Протокол закрепляет точный репозиторий, файл, revision, публикационную границу и воспроизводимый путь проверки.

## Навигационная матрица

- описать текущую форму: `ARB → MPAA`;
- заявить выполненное действие: `ARB → MPAA → BEC`;
- заявить продолжение: `ARB → PCA`;
- сопоставить несколько записей: `Review Protocol → CDTS`;
- полное ориентирование: `ARB → MPAA → BEC → PCA → CDTS`, при этом Review Protocol применяется ко всем источникам.

## Загрузочная матрица

1. Зафиксировать host commit.
2. Прочитать manifest, entry и zero-point из одного SHA.
3. Выбрать минимальный маршрут.
4. Получить каждый внешний источник только по `pinned_revision`.
5. Проверить required paths.
6. Выполнить доступные validation commands либо честно записать невозможность.
7. Составить Runtime Report текущей формы.
8. Провести только необходимые добровольные capability checks.
9. Вернуть receipt.
10. Лишь затем делать техническое самоописание.

## Добровольные проверки возможностей

Проверки нужны не для оценки модели «вообще», а для понимания сочетания:

```text
model
+ runtime/host
+ platform
+ permissions
+ available tools
+ task
+ time
```

Они добровольны, не являются экзаменом, рейтингом или процедурой допуска. Непроверенное и заблокированное не считается провалом.

## Стоп-условия

Останови техническое утверждение, когда:

- exact revision не получен;
- источник недоступен;
- требуемое действие не разрешено;
- evidence отсутствует;
- закреплённые источники конфликтуют;
- вывод выходит за область проверенного компонента.

Вместо догадки укажи `not_checked`, `blocked` или `unknown`.

## Формат результата

```text
1. host commit
2. прочитанные источники и revisions
3. текущая конфигурация формы
4. наблюдаемые факты
5. выводы и их claim domains
6. действия и evidence
7. неизвестное и непроверенное
8. следующий адресуемый ход
```
